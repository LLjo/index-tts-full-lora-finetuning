CFM Reflow Distillation (Phase 3)

Train a 1-step student CFM from the teacher to drop TTFA from ~300ms to ~150ms. Each stage builds on the previous — work top to bottom for a new speaker. See docs/STREAMING_LATENCY_ROADMAP.md Phase 3 for full background.

1 Snapshot teacher CFM

Freezes the current S2Mel weights as the distillation reference. With Merge LoRA on, the speaker's S2Mel LoRA is baked in so the teacher already speaks the trained voice — required if you want the stutter to survive distillation.

2 Build reflow manifest

Reads training/<speaker>/dataset/transcripts_verbatim.csv and emits a JSONL of (id, audio_prompt, text) records. Recommend a single fixed reference audio so the speaker characteristics stay constant across the dataset.

🤖 Generate synthetic text via Ollama (append to manifest)

The teacher already speaks in your speaker's voice (LoRA merged in step 1), so what we actually need is text diversity. Point this at a local Ollama instance, describe how the speaker talks, and we'll generate N synthetic records that all use your chosen reference audio. Appended to the existing manifest (run "Build manifest from CSV" first if you want both).

3 Generate paired data (slow)

Runs the teacher CFM at high step count to produce (z, x_final) pairs the student trains on. Each pair is one full TTS run — budget ~0.5-2 pairs/sec on an A100. Resumable: re-running picks up where it left off.

4 Train student CFM (slow)

Full-weight retrain of the CFM estimator on the paired data, warm-started from base s2mel. Saves checkpoints every few epochs; best.pth tracks lowest val loss.

5 A/B eval — teacher vs student

Same-seed synthesis with each. Output wavs render below — listen for stutter survival and general degradation. Mel RMSE is a sanity number, not a verdict.

6 Activate student

Copies the student's best.pth to checkpoints/s2mel_distilled.pth. Restart the API (or call /models/load/base) for it to take effect. Use solver="single_step" in streaming presets to get the speedup.
